# 无纸化维护中心：故障调查工作台方案

日期：2026-09-20。状态：方案与 HTML 交互原型，待业务验收；未实现 Flutter、排障服务或真实模型接入。

## 一、建议与本次范围

在当前 npl-maintenance 中增加“故障调查”能力，保留现有工单查询作为上下文入口。将 **NPL 江苏定义为一个业务项目，npl-js 与 npl-backend 定义为该项目的两个代码源**，一次调查可以跨仓库关联入口、平台编排和文件处理。

先用独立 HTML 校验布局、取证流程和异常状态，再让同一 HTML 接入真实服务验证合同，最后迁移到 Flutter 原生界面。HTML 不包进 WebView，不在本轮调整现有 Flutter 结构。浏览器阶段明确分开模拟模式和真实模式；真实连接失败必须报错。

本轮新增目录 `design/fault-investigation/`，不改动已有 `design/maintenance-v2/` 和 `lib/`。当前仓库已有未提交修改，本次保留。两个待排障仓库仅做静态阅读，没有访问数据库、Zookeeper、对象存储或业务接口。

## 二、当前事实与参考项目的区别

| 对象 | 当前事实 | 对方案的影响 |
| --- | --- | --- |
| fault-locator | README 明确是设计、合同、fixture、手册与 HTML 开工包；server 和 apps/flutter 为蓝图 | 可以复用协议思想、证据模型与调查状态约束，不能当成可直接启动的后端 |
| npl-maintenance | `lib/core/contracts.dart` 定义工单、报文、签字、图片查询；控制器实现 HTTP、取消、缓存、文件读取、接口记录 | 复用业务上下文与用户入口，不将现有客户端控制器直接搬到服务端 |
| 当前鉴权 | 客户端密钥保存在系统安全存储，查询时生成业务 JWT | 排障服务采用独立身份与权限；不能把客户端私钥或完整认证头随工单上传 |
| npl-js | 江苏定制 Maven 工程；`npl-service-jiangsu/pom.xml` 的父坐标是 `npl-backend:V2.96.jiangsu` | “js”不能按 JavaScript 前端理解；应优先查定制入口、业务实现及装配 |
| npl-backend | `WoService.apply` 按 applyChain 获取并执行 IWoDealer；ObsWrapper 选择加解密适配器 | 继续追踪实际 dealer、平台文件读取和异常传播，不能在项目边界停止 |

设计阅读时 npl-js 的 HEAD 为 `de81ad29`，npl-backend 为 `b7e515d35`。这只是本机 HEAD，不代表工作树无修改，也不代表运行中的部署或依赖版本；本次依据是当前可见源码。落地时需要固定快照并记录制品映射。

### 已核实的首个调查样例

`npl-js/npl-service-jiangsu/src/main/java/com/agile/js/eg/controller/TestController.java`：

- 第 94 行声明 `/un_look`，结合类路径为 `/test/un_look`。
- 第 99–100 行：JWT 校验失败返回 400。
- 第 103 行：`ext8` 传入 `ObsWrapper.wrapper` 后调用文件读取。
- 第 108–109 行：读取及响应处理中的异常同样返回 400。

`npl-backend/npl-backend-api/src/main/java/com/agile/npl/wo/wrapper/ObsWrapper.java`：`wrapper(String encryptType)` 委托 `EncryptionFactory.instance` 选择实现。它证明参数流向，不证明加密标记错误。

因此，“收到 400”只能支撑候选原因，不能确认是存储故障、文件不存在或鉴权失败。原型使用人工构造的工单与接口记录，加上上述代码节选，最终报告为“证据不足”，这是预期产品行为。

## 四、产品流程与高保真界面

### 调查入口

1. 选中工单后点击“发起故障调查”，带入 caseNo、opMonth、当前环境及用户选择的材料引用。
2. 用户补充故障现象和时间；没有工单时，也可从“新建调查”开始。
3. 显示两套代码来源与部署匹配状态；未知版本不得显示为已核对。
4. 顺序展示手册、公开调查动作、工具结果、候选原因与证据缺口。
5. 可补充方向、停止调查、允许或拒绝一次敏感读取。
6. 报告包含现象、根因状态、证据、已排除项、建议，以及尚未验证项；证据点击回到保留片段。

### 布局与视觉

采用维护中心现有风格：主蓝 `#2869e8`、深墨 `#203149`、蓝灰背景 `#f3f6fa`、浅边线 `#e5ebf3`，成功绿 `#26886b` 与候选原因琥珀 `#b17922`。标题使用系统中文字体中等字重，正文使用系统无衬线字体，路径和单据使用 Menlo/Consolas。

桌面为左侧入口与历史、中间调查内容、右侧工单与代码源。中屏收起上下文栏，必要信息仍在范围栏、证据和项目页可查；手机使用单栏和顶部入口。特点是可点击的跨仓库调用链，而非大面积聊天气泡。

本轮可操作功能：新建调查、切换会话、搜索会话、工单带入、调查/证据/报告切换、展开工具、查看代码和记录、补充方向、模拟审批允许/拒绝、停止与继续、添加附件文件名、导出 Markdown 报告、项目与数据源预览。

模拟说明：任意自定义描述均回放同一个 PDF 样例，不能进行真实自然语言诊断。附件只显示文件名，不上传、不解析。模拟会话仅在页面内存保留，刷新重置；切换记录时未完成的模拟步骤停止。生产实现需要服务端会话持续运行并支持订阅切换，不照搬这个演示限制。

## 五、推荐技术架构

```text
当前阶段：HTML + CSS + JavaScript → 显式模拟事件 → 调查 / 证据 / 报告

后续真实阶段：
HTML 调试客户端 ─┐
Flutter 原生端 ──┴→ 单 Node 调查服务（HTTP / WebSocket）
                       ├→ 调查协调器 / 权限 / 审批 / 脱敏
                       ├→ Pi adapter → 已批准的模型端点
                       ├→ 受控工具 → 固定代码快照 / 一个日志来源 / 已登记只读接口
                       └→ PostgreSQL 事件与审计 + 本地证据持久卷
```

Node/TypeScript、Pi、HTTP/WS 和 PostgreSQL 延续参考方案方向，具体运行时及依赖版本在后端开工阶段重新核验并锁定，本轮不进行选型时效性或 SDK 兼容性声明。无需先引入 Redis、向量库、多 Agent 或独立 Python 业务服务。

### 两条连接分开

现有 Flutter → NPL 业务接口的手工查询通道继续独立。调查客户端 → 调查服务是新的身份会话和服务地址。调查服务若需读业务数据，优先使用管理员登记的专用只读身份及接口，不代理任意 URL，不自动接收客户端密钥。

如果首期没有服务端业务凭据，可以先接收用户选择、脱敏后的工单材料与日志，完成“材料 + 固定代码”的真实分析。是否转发既有短期业务令牌须另行确认认证协议，本方案默认不转发。

### 多仓库与版本关联

Workspace 包含 repoId、固定 commit、模块根目录、制品坐标与部署映射状态。npl-js 的父 POM 坐标不足以证明生产加载的是本机 npl-backend HEAD；需结合实际依赖制品、源码版本和环境部署信息校对。服务端检索通过仓库白名单与相对路径运行，防止路径越界和符号链接跨范围。

### NPL 专用取证入口

| 方向 | 优先材料 | 查阅代码 |
| --- | --- | --- |
| 工单缺失、查询无结果 | caseNo、sysAccept、opMonth、时间范围、接口响应 | 当前查询契约、实际后端查询实现与分表逻辑 |
| PDF 无法读取 | 文件引用、bucket/objectName/ext8、HTTP 记录、读取异常 | TestController.download4Obs → ObsWrapper → ObsHandlerWrapper / 实际存储实现 |
| 办理链路失败 | 受理流水、工单号、环节名、result/stepName、关联日志 | WoService.applyChain → 实际 IWoDealer → 江苏定制覆盖 |
| 报文、签字、图片不一致 | 关联表查询结果、月份、文件映射与脱敏材料 | 对应业务入口及平台保存/读取环节 |

第一条真实闭环建议选 PDF 读取：入口清楚、跨仓库边界明确、当前客户端已有请求记录。其余方向先形成手册，不同时开发多个适配器。

Zookeeper 不开放给模型或调查服务直接操作，沿用目标项目的人工执行边界。需要配置证据时，由人员提供版本、获取时间和脱敏片段，明确其来源与覆盖范围。

## 六、合同与状态设计

下表为拟定领域合同；实现时应以 fault-locator 的 Schema 为基线逐字段映射，不直接把当前 UI 字段视作正式协议。

| 对象 | 核心字段与约束 |
| --- | --- |
| 项目 Project | 项目标识、环境、代码源列表、批准的数据源与手册 |
| 调查 Investigation | 调查标识、项目、发起人、问题、工单引用、范围、创建时间 |
| 运行 Run | 运行标识、固定快照、模型/手册版本、状态；每调查最多一个活动运行 |
| 事件 Event | 调查内连续 seq、运行标识、事件类型、脱敏 payload；落库后发布 |
| 证据 Evidence | 项目/调查/运行归属、源类型、快照、时间或行/页定位、保留片段、hash、脱敏及覆盖信息 |
| 审批 Approval | 单次工具调用、环境、操作版本、参数摘要、用户、有效期、决策；取消后失效 |
| 报告 Report | 现象、根因及状态、引用、排除项、建议、未验证项、版本号 |

浏览器与 Flutter 共享 reducer 的状态语义：排队 → 调查中 → 等待审批 → 调查中 → 完成；停止经过“正在停止”再进入“已停止”。连接中断与调查停止必须分开。重连通过 afterSeq 补齐事件并去重；取消后的迟到结果不能恢复运行；上一轮报告与新运行分开保存。

confirmed 必须具备验证证据及部署版本匹配；suspected 标示支持与反证缺口；inconclusive 用于不足以缩小到根因的情况。零条日志必须附覆盖时间和查询结果状态，不能自动变成“已排除”。

## 七、实施顺序与验收

| 阶段 | 工作内容 | 退出条件 |
| --- | --- | --- |
| P0：本轮 | 当前工程/参考方案分析，独立 HTML 与方案 | 页面交互验证，用户审阅入口、取证、报告与布局 |
| P1：合同与 SDK 核验 | 新建 server；核验实际 Pi 发行导出、工具限制、流式与取消；锁版本；整理项目/代码源合同 | SDK 探针与合同校验通过；缺模型凭据明确标记未验证 |
| P2：HTML 接真实闭环 | HTTP/WS、身份、事件持久化、固定代码、人工脱敏材料、真实 Pi 调查 | HTML 能真实开始/停止、重连回放、查看可追溯证据；无静默模拟回退 |
| P3：NPL 数据适配 | 选择一个真实日志来源，登记只读查询；制品与部署版本关联；敏感读取审计 | 一个 PDF 故障样例完成真实证据调查，并能诚实输出不确定结果 |
| P4：文件与健壮性 | PDF/图片解析、附件权限、审批竞态、异常与恢复 | 格式/大小限制、取消、越权、证据归属及失败路径通过验证 |
| P5：Flutter 原生 | 按已验收布局新增调查模块，连接同一协议 | 桌面/手机关键任务一致，原生交互与断线恢复验证 |

不在本轮估算承诺人天。日志接入方式、模型端点可用性、部署权限与证据文件解析范围会直接影响工作量，先完成 P1/P2 能更准确拆分后续任务。

## 八、待确认输入与默认选择

这些内容不阻塞本轮原型，可在真实服务阶段开始前确定：

1. 服务部署位置与访问方式：默认独立内部 Node 服务，而非每台客户端内嵌运行。
2. 日志来源：先提供脱敏文件或一个受控只读查询来源，不假定已有 ES 或日志平台。
3. 模型端点：服务端批准端点，项目材料是否允许发送需明确；原型不需要填写 key。
4. 生产依赖映射：npl-js 部署版本、实际 npl-backend 制品与对应源码版本。
5. 业务只读身份：默认与维护端客户端私钥隔离，不复制密钥进入服务端。

## 九、使用与验证

直接打开 `design/fault-investigation/index.html`，无需安装依赖、无需服务端。HTML/CSS/JS 分文件便于调试，资源全部本地，不依赖 CDN。

建议验收顺序：继续调查 → 允许或拒绝 → 查看报告 → 点击 E02 → 导出；然后新建自定义调查、停止/继续、查看项目与数据源，最后检查手机宽度。

实际执行的页面检查及截图见同目录的《故障调查原型验证.md》。浏览器检查不代表 Flutter、Pi、后端、生产接口或真实故障定位能力已通过验证。
