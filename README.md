# 无纸化维护中心 · NPL Console

基于 Flutter 的原生工单查询与单据图片修复工具。通过工单关联查看 PDF、报文、签字和图片，支持 macOS、Windows、iOS、Android。客户端直接发起 HTTP 请求，不依赖浏览器跨域代理。

## 下载与安装

从 [Releases](https://github.com/kiliter/npl-console/releases) 下载对应平台的 **Release 正式模式**安装包。Release 模式与是否拥有平台信任签名是两回事，具体如下。

| 平台 | 文件 | 签名及安装 |
| --- | --- | --- |
| Windows x64 | `windows-x64-selfsigned.zip` | 完整解压后运行 `npl_maintenance.exe`；构建机生成自签名，非系统信任证书，可能出现 SmartScreen 提示。附带公钥证书仅供核对，无需导入系统信任根。 |
| macOS Apple Silicon / Intel | `macos-universal.dmg` | 打开后拖入应用程序；使用 CI ad-hoc 签名，未做 Developer ID 签名或 Apple 公证，其他 Mac 可能提示无法验证开发者。 |
| Android | `android-release.apk` | 使用独立 RSA 发布密钥签名，可侧载安装；支持 arm64、armv7 和 x86_64。旧版使用 Debug 签名，不能直接覆盖，卸载前请确认可重新导入业务密钥。 |
| iOS 真机 | `ios-unsigned.ipa` | 真机 Release 构建，未签名；需使用自己的 Apple 开发者证书和设备描述文件重新签名后安装，不是模拟器包，也不能直接安装。 |

四端安装包均由 GitHub Actions 构建并上传，无需在本机下载产物进行哈希校验。安装包不内置业务私钥、密码、服务地址或查询数据。具体系统最低版本以构建产物和平台配置为准。

## 首次使用

1. 打开应用，桌面点 **设置**，手机点 **更多操作 → 连接与密钥设置**。
2. 配置一个或多个环境：每个环境填写名称和服务地址（包含实际部署上下文，不要额外拼上 `/api`），web 地址可选，仅日志文件功能使用；圆点选中的为当前环境。JWT 工号、渠道和 OBS 桶覆盖对所有环境通用。保存后可在桌面顶栏或手机 **更多操作** 中快速切换环境，切换会清空当前结果与缓存。旧版单个服务地址自动迁移为「默认环境」。
3. 选择自己的 `.keystore` / `.jks` 密钥库并输入密码；也支持 PKCS#8 PEM / DER。私钥密码与库密码相同时可留空。
4. 点击搜索入口，选择 **手机号码、受理流水或单据号**。手机号/流水默认查单月，可切换范围；首尾合计最多 12 个月。
5. 从结果中选择工单，再查看单据信息、PDF、报文、签字或图片。范围查询展示进度，可取消并保留已完成月份。
6. 下载按钮通过系统文件选择器保存原始文件；接口记录可查看真实 URL、方法、请求与响应。

### 搜索历史与缓存

- 本地保留最近 **30 次合法提交**的查询条件，重启后恢复；失败或取消的查询也保留。点击历史回填条件，再点击查询；清空会同步删除本地历史。
- 接口请求完成后追加到系统应用数据目录的 `request-logs/requests-*.jsonl`，每次启动使用独立文件并立即刷新；实际路径在“接口调用记录”中展示。日志保留完整文本请求和响应以供分析，文件下载只记录大小和类型，不记录认证头、JWT 或密钥。历史文件不会自动删除。
- 历史包含查询号码和月份，只保存本机。接口成功响应在内存中缓存 5 分钟，最多 128 条 / 64 MiB；失败不缓存。
- 桌面缓存按钮或手机菜单可清空缓存；文件重新读取和关联列表刷新会主动请求。

### 单据信息与文件阅读

- 根据 `WO_INFO202610` 建表字段显示单据，排除额外 Bean 属性。
- 普通字段无数据（null、空白字符串、空集合）时隐藏；**EXT1～EXT10 全部保留**。0 与 false 属于有效值。
- 字段支持搜索、分组折叠、完整长值、复制和 JSON 导出。导出采用相同字段规则，接口日志保留原始响应。
- 桌面支持详情与 PDF 分栏、拖动分隔线；PDF 使用原生 PDFium 连续阅读，支持缩略图、页码跳转、适应宽度/整页和缩放。
- PDF、文本、图片的全屏仅覆盖 **App 内部**，不会切换 macOS 系统桌面；Esc 或退出按钮返回。
- 报文支持 JSON/XML 解析、字段折叠、Key/内容搜索，以及嵌套字符串与 CDATA 逐层专注；面包屑返回上层。
- 多张图片和签字在同一画廊连续展示，单图支持下载、全屏和读取失败重试。

### 单据图片修复

1. 填写新老单据号并加载。两侧连续滚动，缩略图和进度条双向联动。
2. 左侧右键可「在左侧复制为镜像页」或「复制此页到右侧」，选择插入位置；右侧右键可复制本页到指定页下面。
3. 在左侧按住 Ctrl / ⌘ / Shift 多选图片并加入共享区，按左右当前页序和原坐标实时预览。镜像页可独立选图。
4. 右侧点击或右键图片可删除，或「移入共享区暂存」后从原位移除；将紫色暂存卡片拖到右侧任意页面即可重新放置。右键页面可恢复本页删除的原图。共享区移除图片也会立即更新画布。
5. 本地图片导入时选择页码、位置和宽度。共享区以小图区分“旧图”和“本地”。
6. 点击「应用」生成修复后的 PDF，再「保存到本地」。预览阶段不反复生成 PDF，不重载右侧单据。

不再需要选择页码关系或设为跳过。只有页数不一致时显示提示；超出新单据页数的图片暂不写入，补页后再应用即可。不会自动镜像或复制页面。保存不自动覆盖 OBS。实现说明见 [单据图片修复说明](docs/PDF_EDITOR.md)。

### 密钥保存

连接环境、查询历史、更新代理配置和业务签名密钥统一保存在 `~/.config/npl-maintenance`（手机使用应用目录下 `.config/npl-maintenance`）。macOS/Linux 目录权限为 `700`、文件权限为 `600`；密钥存为专用 `signing-key.json`，不另设本地文件密码，覆盖更新后直接读取，不再依赖应用签名触发钥匙串授权。

旧配置按项迁移；旧业务密钥读取、解析、写入和读回验证成功后才删除本应用的旧钥匙串条目，并验证删除结果。迁移失败保留旧副本；首次迁移可能仍需批准一次旧钥匙串访问。业务密钥本身不作废，原始 JKS / PEM 文件不修改。导入密码和 JWT 不持久化，日志不记录私钥。

业务 JWT 密钥与给安装包签名的发布密钥是不同用途，不能混用。

## 接口契约

所有请求均为只读业务查询。当前客户端适配以下接口；服务端须实现相同契约。

| 内容 | POST 路径 | 请求 |
| --- | --- | --- |
| 工单 | `/api/wo/queryList` | `caseNo` 或 `sysAccept/phoneNo + opMonth` |
| 报文 | `/api/wobiz/queryList` | 选中工单的 `caseNo + opMonth` |
| 签字 | `/api/wosign/queryList` | 同上 |
| 图片 | `/api/wopic/queryList` | 同上 |
| 接口结果 | `/api/inter/result/queryList` | `caseNo` 或 `sysAccept + opMonth`，可选 `interUrl`、`retCode` |
| 全量报文 | `/agapi/biz/downloadBiz` | `caseNo`，返回 `{result, data, desc}`，`result` 为 0 时 `data` 为报文内容 |
| OBS | `/test/un_look` | 表单 `bucketName + objectName + ext8` |
| 日志列表 | `/log-file/list` | JSON `{dir}`，返回注册中心中全部副本的一层目录 |
| 日志分片 | `/log-file/download` | 查询参数 `instance + path + offset + fileKey`，返回 1.5MB 二进制分片 |

JWT 使用 RS256，有效期 20 分钟，通过 `kkk` 与 `agAuthorization` 请求头发送。HTTP 出口限制为上述路径（另有独立确认流程的 OBS 上传 `/test/look`），不包含新增、修改、删除接口。默认保持系统 HTTPS 校验，不跟随重定向。

「日志文件」面板浏览服务或 web 全部副本的 `/usr/local/logs`：点击目录进入，点击文件后选择保存目录，按 offset 逐片下载，每片收到即追加写入磁盘上的 `.part` 文件（内存只保留当前一片），以首片 `X-File-Size` 为准，完成后改名为正式文件，失败或取消自动删除 `.part`；文件名带 Pod 前缀区分副本。手机端固定保存到应用文档目录下的 `log-files`。下载中文件被轮转（HTTP 409）时，按 `fileKey` 在同一副本同一目录重新定位后续传；每个分片都会写入接口记录。服务端接口由 npl-js 的 `LogFileController` 提供。

「批量下载」按文件名通配符（同 `ls *.log`：支持 `*`、`?`、`[abc]`，多个模式空格分隔，整名匹配、区分大小写，不含目录、不进子目录）过滤当前目录下全部正常副本的文件，确认后选择保存目录，在其中新建 `<server|web>_logs_<时间>` 文件夹，逐个下载并直接写盘：按 Pod 分目录，个别文件失败不中断，失败原因写入「下载失败清单.txt」；匹配到的文件全部下载，不限制合计大小。

「数据查询」面板支持 WO_INFO / WO_BIZ_INFO / WO_SIGN_INFO / WO_PIC_INFO / SYS_INTER_RESULT，复用对应的既有只读接口。请求体为按表组合的非空条件：`caseNo`、受理流水（图片表发送 `picSeq`，其余表发送 `sysAccept`）、`opMonth`（`YYYYMM`，定位月份分表）；至少填写一个条件，按受理流水查询须搭配业务月份。结果以表格展示，点击行查看完整字段。

### 接口结果查询与解密

选择「接口结果表」，填写单据号，或受理流水和业务月份。单据号的月份由服务端解析，优先于显式月份；不允许只按月份扫描整张结果表。可选填接口标识（签字识别为 `signcheck`）和原始返回码，不填写时不过滤接口类型或返回码。

在面板中输入获授权的原始 SM4 密钥（UTF-8 编码恰好 16 字节，不进行十六进制转换或去除首尾空格）。查询后自动在本地解密 `retMsg`、`retDetail`、`paramInt`，也可以查询后输入密钥点击「本地解密」。解密在后台执行，清除或修改密钥、切表、重新查询、关闭面板后，旧任务结果不会回写。实现与 npl-js 的 `CrmFieldEncryptService` / `Sm4EcbPkcs5` 对齐：`SM4:` + Base64，SM4/ECB，16 字节分组填充；无前缀内容原样展示。部分字段失败时显示失败数量并保留相应密文，不把失败当作解密成功。ECB 密文不具备认证能力，填充与 UTF-8 校验不能替代完整性认证。

密钥仅用于当前查询面板，不发送到服务器、不写入配置、钥匙串或请求日志。解密生成新的展示记录，不修改响应缓存和原始请求日志；服务端本身返回的明文仍遵循现有原始响应日志策略。修改密钥会恢复原始结果；「清除密钥及明文」恢复原始结果，切换表或关闭面板释放会话内容。Dart 托管字符串不保证立即物理擦除。复制字段或 JSON 是主动导出当前内容，解密后会包含明文，请留意系统剪贴板。

## 本地开发与构建

固定 Flutter **3.44.7** / Dart **3.12.2**，依赖版本见 `pubspec.lock`。macOS/iOS 使用 Xcode，Android 使用 Android SDK 与 JDK 17，Windows 使用 Visual Studio 2022 C++ 桌面开发工具和 Windows SDK。

```bash
flutter pub get
flutter analyze
# PDF 测试复用本机生成的原生库，macOS 首次先构建：
flutter build macos --release -t lib/main.dart
flutter test
```

PDF 原生控件测试在 macOS 默认读取 `build/native_assets/macos/libpdfium.dylib`，其他环境通过 `PDFIUM_PATH` 指定本机对应动态库。测试夹具的 `sample.jks` 是独立生成的测试密钥，密码公开仅为测试用途，严禁用于业务环境。

四端构建和签名步骤见 [发布构建说明](docs/BUILD_RELEASE.md)。推送 `v*` 版本标签自动触发[四端正式发布工作流](.github/workflows/release.yml)，全量测试和四端构建全部成功后自动发布。

## 目录

- `lib/core/`：查询、OBS 映射、缓存、JWT、系统安全存储。
- `lib/ui/`：双端布局、搜索历史、详情、PDF、报文与画廊。
- `design/maintenance-v2/`：已确认的双端 HTML 原型，使用演示数据。
- `test/`：单元和控件测试，不连接真实业务后台。
- `docs/releases/`：版本发布记录；[CHANGELOG](CHANGELOG.md)。

构建与自动化测试不等于真实设备上的全部功能验收；本轮发布不额外操作业务 UI。
